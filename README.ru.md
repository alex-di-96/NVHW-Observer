# NVHW-observer

Инструменты исследования GPU: инвентаризация, проверка журналов UEFI и реальные
OpenGL-тесты. **Development preview 0.2.0.dev0**, Linux, Python 3.10+.

Главный принцип: заявленная возможность, создание сессии, выполненная работа,
проверенные данные и фактический способ выполнения — отдельные результаты.
Успешный снимок регистров не означает включение NVDEC, NVENC или RT-ядер.

Новый [отчёт M3 от 18 ноября](docs/research/2026-11-18-lifecycle-m3.md#русское-резюме): пять фаз UEFI, совместные проверки кодеков/RT/OpenGL/compute и следующие точки исследования. [JSON-сводка](docs/research/2026-11-18-lifecycle-m3-summary.json). Публичный код M1/M2 не менялся.

В состав входят:

- PCI-инвентаризация без доступа к BAR, конфигурационному пространству и ROM.
- Строгие офлайн-парсеры журналов v6 и M1/M2.
- OpenGL через EGL с проверкой каждого пикселя двух изображений.
- GLX и опциональный обмен буфером64КиБ между OpenGL и CUDA.
- Исходники пассивного UEFI observer и синтетические QEMU-проверки.

Установка из каталога исходников:

```sh
python3 -m venv .venv
. .venv/bin/activate
python -m pip install .
nvhw-observer --version
nvhw-observer inventory --output inventory.json
```

Инвентаризации не нужны права администратора. Для реального OpenGL-теста
укажите PCI-адрес нужной карты из полученного отчёта:

```sh
nvhw-observer test-opengl --bdf 0000:01:00.0 --output opengl.json
```

В UEFI квалифицирована одна конкретная CMP50HX/TU102 с проверкой идентичности
платы и ROM. GTX1060, RTX3070 и CMP70HX пока входят в план сравнений.
Внешний compute-загрузчик не включён: публичная сборка не является готовой
универсальной загрузочной флешкой. Автоматической прошивки или перезагрузки нет.

Разблокировка выделенных NVDEC/NVENC и аппаратного RT не подтверждена.
Рабочий JPEG через CUDA и другие результаты стенда описаны отдельно;
портативных команд JPEG, VDPAU, CUDA и Vulkan в этой версии ещё нет.
